# تسعيرة

تطبيق عربي لمقارنة عروض المنتجات من متاجر السعودية والصيدليات باستخدام Next.js وTypeScript. يبحث بالتوازي، يعرض النتائج تدريجيًا، ويسمح باختيار عرضين إلى أربعة لمراجعة حجم العبوة وسعر الوحدة وروابط المصادر.

## التشغيل

Node.js 24 موصى به (الاعتماديات تتطلب 20.18.1 أو أحدث).

```powershell
npm ci
npm run dev
```

افتح http://localhost:3000.

```powershell
npm run typecheck
npm test
npm run build
```

## المتاجر

المفعّلة: الدانوب، كارفور، التميمي، نينجا، بن داود، أمازون السعودية، هنقرستيشن، نون ماركت (noon Minutes)، وصيدليات النهدي والدواء والمتحدة ووايتس وإنوفا، ومتجر دار الأميرات للعناية والجمال.
الربط المباشر للولو والعثيم والسدحان غير مفعّل؛ العثيم متاح حاليًا عبر هنقرستيشن. لا توجد نتائج وهمية.

مواقع السعر تختلف: الدانوب مرتبط بالريان/الروابي وبن داود بالمرسلات/بانوراما في الرياض. بقية الموصلات تستخدم السياق الافتراضي المعلن في بطاقات المنتجات. لم يتم اختيار عنوان توصيل مستقل لكل متجر.

هنقرستيشن يجمع أول 20 نتيجة لكل من العثيم وبنده والتميمي من فروع الموقع الافتراضية بالرياض. اسم السوبرماركت والحي يظهران على العرض، والتوفر غير مؤكد. يُعلن فشل أي فرع كتغطية جزئية، وفشل الثلاثة يعرض خطأ قابلًا لإعادة المحاولة. لا يمثل عنوان توصيل المستخدم أو كل متاجر المنصة.

نون ماركت يقرأ الصفحة الأولى من نتائج كتالوج السعودية العام، بما فيها الإعلانات والبدائل. الأسعار الحالية والأحجام وروابط المنتجات والصور من الصفحة نفسها. عنوان التوصيل غير محدد، والتوفر غير مؤكد ما لم يُعلن المصدر نفاد المخزون صراحةً.

الواجهة تجمع «الكل / المقاضي / الصيدليات / العناية والجمال» في بحث واحد، مع حفظ القسم والاختيارات. النهدي أول صيدلية مفعّلة؛ الأسعار من الكتالوج السعودي العام دون عنوان أو طريقة شحن محددين. تفاصيل تجربة الأقسام والافتتاحية والمقارنة في [مستند الصيدليات](docs/pharmacies-ux.md).

ليمون غير مفعّلة مؤقتًا: قارئ المنتجات يعمل محليًا، لكن المصدر يرفض طلبات Vercel برمز 403. لا يُستخدم مؤشر اقتراحات البحث كبديل لأن بعض أسعاره اختلفت عن صفحة المنتج.

## المسار

`apps/web` للواجهة و`GET /api/search?q=...&city=الرياض&store=...`؛ `packages/core` للعقود والتحقق من النتائج والكميات والصلة وإدارة المهلة؛ `packages/connectors` لربط المصادر على الخادم فقط.

كل طلب متجر مستقل في الواجهة. فشل متجر لا يمسح نتائج الآخرين. يمكن الإيقاف وإعادة المحاولة. للبحث المشترك، API يقبل أكثر من `store` أو جميع المتاجر عند إغفاله.

السعر موجب وبالريال ورابط المنتج يجب أن ينتمي لمتجره. الاتصال يعيد المحاولة بحد أقصى مرتين لأخطاء شبكة مؤقتة، داخل نفس مهلة العشر ثواني، مع IPv4 بديل. لا يعيد محاولات HTTP المرفوضة أو أخطاء التحليل تلقائيًا.

## حدود المقارنة

النتائج ليست مطابقة مؤكدة لنفس المنتج. «الأقرب للبحث» فلتر مساعد، والمقارنة باختيارات المستخدم. الكميات مستخرجة من الاسم بشكل محافظ؛ المختلف أو المجهول له تنبيه. الأسعار لا تشمل التوصيل، وقد تختلف حسب الفرع والعنوان والبائع والتوفر. أول صفحة فقط لكل مصدر.

الواجهة تبدأ من الجوال: اختيار متاجر بنافذة سفلية، أزرار ترتيب مباشرة، بطاقات مختصرة وشريط مقارنة سفلي. الكمبيوتر يحتفظ بتخطيط أوسع.

آخر خمس عبارات بحث واختيارات المتاجر تحفظ في متصفح المستخدم ويمكن مسح السجل. لا يوجد حساب أو إرسال لخدمة تحليلات خارجية.

راجع [خطة المنتج](docs/product-plan.md) و[مراجعة الموصلات](docs/connector-audit.md) و[المعمارية](docs/architecture.md).

## النشر

المشروع الحالي ينشر عبر GitHub إلى Vercel ويحتاج Node.js؛ ليس تصديرًا ثابتًا. لا تحفظ أسرارًا في المستودع أو متغيرات `NEXT_PUBLIC_`. ملفات التقاط البحث وتقارير الاختبار المحلية مستبعدة من Git. قبل توسيع الاستخدام: قياس الموثوقية والتكلفة، تخزين مؤقت معلن، تحديد معدل مشترك ومصدر هوية موثوق للمطابقة الآلية.

## توصيات الجمهور

تحتاج Upstash Redis مربوطًا بالمشروع (يمكن اختيار Free ضمن حدود المزود). متغيرا الخادم هما `UPSTASH_REDIS_REST_URL` و`UPSTASH_REDIS_REST_TOKEN`، أو الاسمان اللذان تضيفهما بعض تكاملات Vercel: `KV_REST_API_URL` و`KV_REST_API_TOKEN`. لا تستخدم read-only token لأن نشر التوصية يحتاج كتابة. بعد الربط يلزم نشر جديد.

تُجمع التوصيات لكل منتج ومتجر بشكل ذري، وتُحسب توصية واحدة لكل هوية متصفح موقعة. هذا ليس تحققًا من أشخاص حقيقيين؛ مسح الكوكيز يغيّر الهوية. لا تُجمع عناوين IP. يوجد حد 30 محاولة كتابة في الدقيقة لكل هوية، وحد أقصى 10 آلاف توصية للمنتج.

لكل deployment مساحة مفاتيح مستقلة؛ يبدأ الإصدار الجديد بعدادات فارغة دون حذف بيانات الإصدار السابق فورًا. تنتهي مفاتيح المنتجات القديمة بعد 30 يومًا من آخر كتابة. عند غياب التخزين أو فشله لا تعرض الواجهة نجاحًا وهميًا ولا تؤثر التوصيات على نتائج البحث العادية.

في `next dev` فقط، عند غياب مفاتيح Redis، تعمل التوصيات بذاكرة مؤقتة محلية مع تنبيه ظاهر للمطور. تُمسح عند إعادة تشغيل العملية، ولا تستخدم إطلاقًا على Vercel أو بناء الإنتاج. زر التوصية يبقى ظاهرًا عند تعذّر قراءة العدادات، والكتابة تؤكد نجاح الحفظ من الخادم قبل تغيير حالة الزر.

## مساعد تسعيرة الذكي

زر «ساعدني أختار» يظهر في نتائج البحث. تشغيله اختياري بعد اكتمال البحث: حاجة قصيرة وميزانية اختيارية، ثم حتى 3 خيارات من منتجات المتاجر. الخادم يعيد البحث للتحقق من المنتجات والأسعار، يستبعد غير المتوفر وما تجاوز الميزانية، ويوازن عينة حتى 60 منتجًا بين المصادر. يرى النموذج أسماء وأسعار العينة وتوفرها فقط؛ يعيد معرفات مقيدة ومقتطفًا حرفيًا من اسم المنتج، ولا ينشئ أسعارًا أو روابط. تُعاد مطابقة المعرّفات والمقتطفات مع منتجات الخادم. قد لا يغطي ذلك أفضل منتج في كل الكتالوج، وقد يخطئ النموذج في فهم الاحتياج.

أضف مفتاح OpenAI جديدًا في متغير `OPENAI_API_KEY` بالخادم/Vercel، لا داخل المتصفح أو Git أو المحادثة. `OPENAI_MODEL` اختياري (الافتراضي gpt-4.1-mini). تستخدم الواجهة Responses API مع JSON Schema وstore:false؛ يُرسل إلى OpenAI البحث والاحتياج المدخل وبيانات عينة المنتجات عند ضغط المستخدم فقط. لا ترسل عناوين العملاء أو حساباتهم أو الكوكيز. لا تقدم توصيات علاجية أو بدائل أدوية. store:false لا يعني إلغاء جميع سياسات احتفاظ المزود؛ راجع سياسة بيانات OpenAI عند تحديد سياسة خصوصية المنتج.

في الإنتاج يلزم Redis المتصل أصلًا بالمشروع: سقف مشترك `AI_DAILY_LIMIT` افتراضيًا 100 محاولة جديدة يوميًا بتوقيت الرياض، و3 محاولات لكل عنوان شبكة خلال 5 دقائق. يحتفظ Redis ببصمة HMAC للعنوان لأغراض الحد، لا العنوان الخام؛ لا يرسل العنوان إلى OpenAI. السقف يحجز المحاولة قبل تحديث المصادر/استدعاء النموذج، لذا يشمل محاولات قد تفشل دون تكلفة نموذج. هذه حدود طلبات، وليست ميزانية مالية بالدولار. التخزين المؤقت 180 ثانية داخل إصدار النشر نفسه لتقليل الطلبات المتكررة؛ يظل وقت جلب سعر المنتج محفوظًا. لا يعمل المساعد في الإنتاج عند غياب المفتاح أو Redis. البحث العادي مستقل عن المساعد ويظل يعمل عند تعذره. بعد إضافة متغير المفتاح يلزم نشر جديد.

الاختبارات تستخدم نموذجًا محاكى على مستوى HTTP، ولا تحتاج مفتاحًا حقيقيًا أو إنفاقًا. التحقق الحي من OpenAI يُجرى بعد إضافة المفتاح الجديد من مالك المشروع.
